# Локальное чтение каталога, протокол v1

Все три инструмента требуют `fileKey`. MCP возвращает `structuredContent` с внешним полем `result` (ответ Plugin API), `operationStatus:"read"`; первый `content` block содержит тот же JSON как текст. Поля ниже находятся в `structuredContent.result`. Ошибка возвращает `isError:true`. Во всех успешных результатах есть `schemaVersion:1`, `kind`, `fileKey`; `pageId` обязателен для сканирования и примера. Страница Figma Desktop и выделение не меняются.

* `read_catalog_inventory({fileKey,nodeId?})` → `{kind:"inventory",pages:[{id,name}],complete:true,sourceScope?}`. `sourceScope` содержит `{nodeId,nodeType,nodeName,pageId,pageName}`. Читает все страницы, включая пустые. `nodeId` адресуется точно, в том числе для synthetic descendant.
* `scan_catalog_page({fileKey,pageId,nodeId?,mode:"roles"|"manifest"|"resources",cursor?,limit?,componentIds?,manifestFingerprint?})`. `nodeId` ограничивает область внутри страницы. Для `roles` и `manifest` `limit` по умолчанию 100, максимум 200. `cursor` — непрозрачная строка; передавать только полученный `nextCursor`. Каждый фрагмент содержит `{rootNodeId,complete,cursor,nextCursor,offset,total,fingerprint,coverage:{returned,total},unreadNodeIds,unreadNodeCount,unreadNodeIdsComplete}`. Устаревший cursor отклоняется. `manifest` возвращает срез `componentIds[]` и `manifestFingerprint` полного упорядоченного списка. Склеивать срезы по `offset` до `complete:true`, сверять одинаковые `fingerprint`, `manifestFingerprint`, `total` и отсутствие повторов. `roles` возвращает срезы `componentIds[]` и `exampleCandidates[]`; один cursor идёт по объединению всех ID компонентов и затем всех кандидатов. `counts` содержит полные количества обоих массивов, `total` равен их сумме. Склеивать массивы отдельно в порядке фрагментов; `fingerprint` вычислен по полным массивам и совпадает с каноническим `catalog-source-roles.mjs`. Кандидат набора содержит `variantIds[]` всех активных вариантов. Ветки с `DEPRECATED` в имени или описании исключаются.
* Для `mode:"resources"` нужны 1–8 уникальных `componentIds` из полного manifest и его `manifestFingerprint`; `cursor` и `limit` запрещены. Ответ `{kind:"resource-batch",rootNodeId,manifestFingerprint,componentIds,complete:true,scanComplete:true,coverage:{componentIds,representedComponentIds},counts,components,variables,styles,gaps}`. `representedComponentIds` должен совпасть с запрошенными ID после сортировки: каждый компонент есть в `components` или явном gap. Наборы и варианты имеют разные `kind`. Статус публикации читается через `getPublishStatusAsync`; допустимы `CURRENT`, `CHANGED`, `UNPUBLISHED`. Недоступные статусы и связанные ресурсы дают явные `gaps`; опубликованные ключи нельзя восстанавливать из ID. Повторные variables/styles между батчами следует дедуплицировать при слиянии.
* `read_catalog_example({fileKey,pageId,nodeId,cursor?,limit?,includePng?,screenshotScale?})` → `{kind:"example",rootNodeId,nodes,gaps,complete,cursor,nextCursor,offset,total,fingerprint,coverage,unreadNodeIds,unreadNodeCount,unreadNodeIdsComplete,screenshotNodeId}`. `limit` по умолчанию 100, максимум 200. `nodes` идут в порядке обхода дерева. Каждый узел содержит точные `id,parentId,childIds,childIndex,type,name,properties`; экземпляр дополнительно содержит `mainComponent` с `status:"resolved"|"missing"|"unavailable"`. Тексты, textSegments, ссылки, стили, Variables, paints, layout и геометрия находятся в `properties`; недоступные поля отмечены в `gaps`. Склеивать срезы по `offset` и общему `fingerprint` до `complete:true`, затем проверить точное покрытие всех `childIds`, включая synthetic IDs. При `includePng:true` внешний `structuredContent.screenshot` содержит `status:"captured"` и метаданные или `status:"failed"` с причиной; PNG в отдельном втором MCP `content` block типа `image` с `mimeType:"image/png"`. Base64 не включается в JSON. У снимка hash не вычисляется сервером: архиватор может хешировать bytes image block. Снимок запрашивается независимо для каждого вызова с `includePng:true`; обычно достаточно первого фрагмента.

`complete` описывает полноту *ответа данного режима* относительно выбранной области, а не публикацию или пригодность гайда. Для результатов с `complete:false` обязательно продолжение через `nextCursor`. Все вызовы read-only, не требуют выбора текущей страницы и не выполняют import или setter.

`unreadNodeCount` — точное число ID после текущего среза. `unreadNodeIds` показывает только следующую порцию, не более `limit` ID; у ролей порядок совпадает с единым cursor по ID компонентов и примеров. `unreadNodeIdsComplete:false` означает, что перечислена лишь часть остатка. При `complete:true` всегда `unreadNodeIds:[]`, `unreadNodeCount:0`, `unreadNodeIdsComplete:true`.

Fingerprint примера фиксирует ID, типы, имена, связи родителей и детей, а также текст узлов. Он позволяет обнаружить изменение топологии при чтении нескольких фрагментов. Изменение только цвета, стиля или других свойств между вызовами может не изменить fingerprint; такой обход не является транзакционным снимком всех свойств. Для доказательства согласованности оформления перечитайте затронутый пример.
