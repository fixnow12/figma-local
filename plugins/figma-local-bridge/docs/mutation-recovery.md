# Результаты записи и безопасное продолжение

Контракт добавлен совместимо: прежние вызовы и поведение replace остаются доступны. При свежем адресном get_status нужны diagnostics.ready/current и capabilities `mutation-receipts-v1`, `render-target-parent-v1`. Старый запущенный plugin не гарантирует поздние receipts. Обновление установленной копии и повторное открытие plugin выполняются отдельно после review; исходники сами по себе не подтверждают версию пользовательского процесса.

## Идентичность запроса

`render_screen` и `patch_nodes` принимают необязательный UUID `operationId`. Сохраняйте его до записи. Broker журналирует эти мутации также без явно заданного UUID, возвращая сгенерированный ID в результате/ошибке. DryRun не журналируется как запись. `get_operation_status({fileKey,operationId})` читает журнал без очереди холста: исходные аргументы, argsHash, outcome и result/error. Plugin relay сохраняет поздний результат/ошибку даже после timeout MCP; если он не доставлен, запись остаётся unsettled/unknown и блокирует следующую запись. Отсутствие результата не означает отсутствие изменения.

Один UUID обозначает один запрос: повтор отклоняется до dispatch; изменённые аргументы с тем же UUID отклоняются. Новая намеренная правка получает новый UUID, даже если её аргументы совпадают с предыдущими. Нет запрета по совпадению хеша всех будущих правок.

После timeout/partial/unknown: прочитать журнал, сопоставить fileKey, operationId, argsHash и operationInput, дождаться settled, затем независимо прочитать затронутые ID/ключи. Settled означает завершение выполнения, а не полноту или правильность макета. При applied и ошибке PNG запрашивать только снимок. Для опечатки, номера или маркера использовать `patch_nodes` с адресным `set`, не заменять composition через `render_screen`.

## CLI и сохранённые ответы

`call-tool.mjs` сохраняет request.json до dispatch, затем raw response.json, result.json и transport.json. Без --output используется уникальный `.tmp-figma/calls/<UUID>`; путь печатается в stderr, прежний JSON stdout сохраняется. Для render/patch CLI назначает UUID до отправки. Существующий request.json блокирует повтор мутации в том же --output до вызова инструмента; прежние файлы остаются неизменными. Для новой правки нужен новый каталог. Это не глобальная блокировка новых правок по содержимому.

Для чтения ошибки: `node scripts/call-tool.mjs --read-response <dir>/response.json`. Если ответа нет, читать request.json/transport.json и журнал по сохранённому UUID. Не запускать runner заново ради head/tail или диагностики. Произвольный внешний runner должен сам сохранять UUID и результат: Bridge не может распознать его новый намеренный вызов без идентичности запроса.

## План только отсутствующего append

`node scripts/plan-patch-recovery.mjs --operation operation.json --read full-read.json --output plan.json` работает offline. operation.json — payload get_operation_status или его поле operation; full-read.json — успешный полный inspect_selection того же файла, охватывающий все append targets и их детей. Планировщик проверяет хеш исходных аргументов, settled, полноту чтения, ID, ключи, типы и родителей. Возвращает `next:null`, если всё уже существует; иначе новый patch_nodes args с новым UUID и только отсутствующими ключами. Он умеет продолжить недостающего ребёнка под уже существующим родителем.

Это предложение, без отправки записи. Если состояние изменилось, требуется новое чтение/план. Наличие ключа не подтверждает оформление: существующие узлы сохраняются, различия исправляются адресно после чтения. `set`, SVG/image и неподдержанные/неполные доказательства не возобновляются автоматически. Новая запись всё ещё проходит штатные проверки конфликтов ключей и rollback Bridge. Нет общего автоматического resume произвольных мутаций и нет автоматического replay unknown native imports.

## Существующий Master

`render_screen.parentId` — точный ID PAGE, FRAME или SECTION на текущей странице; неправильный тип/другая страница отклоняются до создания. Отсутствие поля сохраняет прежнюю PAGE-цель. Новый root всегда FRAME; wrapper SECTION для PAGE/SECTION, wrapper FRAME для FRAME (SECTION нельзя вложить в FRAME).

Сохранены поля sectionId и placement.sectionParentId: при FRAME это совместимые aliases ID/родителя wrapper. Смотрите placement.wrapperType; rootParentId должен равняться sectionId, sectionParentId и destinationParentId — ожидаемому parentId. Независимо inspect_selection rootId и sectionId проверяет их фактические parentId. Имя страницы Master не доказывает вложенность в Master. Ошибка размещения существующего ключа в другом destination блокирует replace; непустой Master не удаляется.

Проверки не доказывают визуальное качество, поведение нативного приложения при фоне/фокусе или причины долгих shell-вызовов. Для этого нужен отдельный разрешённый пользовательский запуск после review и синхронизации установки.
