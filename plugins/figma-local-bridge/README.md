# Переносимый библиотечный шаблон

Контекст файла: `get_file_metadata` читает имя, thumbnail и страницы. `set_file_metadata({fileKey,thumbnailNodeId})` устанавливает thumbnail; необязательный `name` служит только точной проверкой уже установленного имени. Несовпадение — `FILE_RENAME_UNSUPPORTED` / `not_applied` до любых записей thumbnail. Plugin API [не позволяет менять figma.root.name](https://developers.figma.com/docs/plugins/api/DocumentNode/); переименование выполняется отдельно пользователем в Figma, затем подтверждается чтением. Совпадающее имя не записывается; при ошибке откатывается только принадлежащее операции изменение thumbnail.

`capture_library_template({fileKey,pageIds})` выполняет отдельное чтение исходных страниц. Сохраните `result.snapshot` локально. Снимок v2 содержит полное дерево со скрытыми ветками, реальные библиотечные ключи, source-relative пути и точные переопределения. Capture не импортирует и не меняет ресурсы исходника.

`assemble_library_template({fileKey,snapshot,mode:"apply"})` собирает сохранённый снимок в назначении с одной пустой страницей. Единственные внешние ресурсы сборки — опубликованные библиотечные компоненты, стили и Variables по сохранённым ключам. Исходный файл не открывается и не читается. Создаются PAGE/FRAME/SECTION и связанные INSTANCE; определения библиотек не изменяются. V1 не принимается: старые source-local style/variable IDs не переносимы.

`mode:"verify"` только читает marker и проверяет реальное дерево/ключи. Повторный apply возвращает `reused`, сохраняя заполненные Jira-тексты. Отсутствие marker — `TEMPLATE_NOT_MANAGED`; несовпадение marker или структуры — отдельная ошибка, не разрешение на пересборку. Status VARIANT может измениться только на заранее сохранённый вариант того же COMPONENT_SET и при сохранении дерева.

Снимок ограничен 20 страницами, 1000 узлами, глубиной 32 и 2 MB. Корневые контейнеры имеют закрытый список геометрических/Auto Layout/paint свойств; внутри экземпляров записываются только явные overrides. Поддержаны поля шаблона таски: width/height, visible/locked, characters, fontName/fontSize, fillStyleId/fills, hyperlink, styledTextSegments, textDecoration/textDecorationSkipInk. Mixed текст переносится диапазонами с точными шрифтами и ссылками; Variables и стили — опубликованными ключами, режимы — именами и anchor-переменной коллекции. Неподдержанные поля, изображения/video, внутренние NODE-ссылки, внешние mask/grid/reactions, отсутствующие опубликованные ресурсы останавливают операцию с конкретным кодом.

Успех: `{status,pages,rootIds,instanceKeys,verification,snapshotId}`. `pages` содержит `{sourceId,id,name}`; `rootIds` — `{sourceId,id,path}`; `instanceKeys` дополнительно содержит `libraryKey`. `snapshotId` — SHA-256 проверенного канонического содержимого. Для последующих правок используют целевые `id`, никогда исходные `sourceId`.

Read-back первой сборки проверяет дерево, библиотечные ключи, свойства, явные значения, диапазоны текста и режимы. Он не заменяет визуальную PNG-проверку Figma layout engine. Откат удаляет только созданные узлы/страницы и восстанавливает имя исходной пустой страницы; импортированные ресурсы могут остаться в кэше. При unknown/partial дождитесь idle и выполните verify/read-back; автоматически повторять apply нельзя.

Перед первой записью после импорта ресурсов повторно проверяются пустота назначения, исходная страница, имя и marker; перед записью marker проверяются полный список страниц и фактическое дерево без дополнительного await. Откат проверяет текущих потомков каждого созданного контейнера: если внутри появился чужой узел, контейнер сохраняется, операция возвращает `partial`, а `rollbackErrors` содержит его ID и ID чужих потомков. Ручное изменение имени исходной страницы или marker не перезаписывается. Оставшиеся контейнеры требуют чтения и адресной проверки перед ручной очисткой.

Прямые scalar-привязки внешних FRAME/SECTION (размеры, отступы, интервалы, радиусы, opacity/visible, strokeWeight) сохраняются как опубликованные ключи Variables и восстанавливаются после размеров. Paint-array aliases должны быть представлены в paints; произвольные массивы, неизвестные поля и другие неподдержанные shapes отклоняются как `UNSUPPORTED_TEMPLATE_BINDING`.

Обнаружение команд: `node scripts/call-tool.mjs list capture_library_template`. Вызов остаётся типизированным через `scripts/call-tool.mjs` с `--args` и `--output`; произвольный код/REST не нужен. Проверки без живой Figma: `node --test tests/library-template.test.mjs`, затем `npm test` (интеграционные тесты используют локальный loopback WebSocket).

### Проверка точности guide-fidelity v2

Кандидат `0.3.0+codex.20260920-variable-import` расширяет существующие команды:

- `render_screen` и `patch_nodes`: `listOptions: {type: "NONE" | "ORDERED" | "UNORDERED"}`, `listSpacing`, `indentation`, в том числе в `textRuns`. `listOptions` и `indentation` используют диапазонный API Figma; пустой текст не поддерживает такие диапазоны.
- Эффект `GLASS`: `radius`, `refraction` (0–1), `depth` (от 1), `lightAngle`, `lightIntensity` (0–1), `dispersion` (0–1), необязательные `splay` и `visible`. `splay` сохранён по фактическому чтению Figma; публичные typings его ещё не описывают. Сохранение подтверждается живым read-back. GLASS не поддерживает переменные эффекта.
- Нативные `polygon`, `star`, `booleanOperation` в `render_screen`; boolean требует минимум два дочерних узла. `pointCount` применим только к POLYGON/STAR, `booleanOperation` — BOOLEAN_OPERATION, `vectorPaths` — VECTOR. Внутри экземпляра эти свойства разрешены только как точный no-op. Реальное изменение блокируется до первой записи; экземпляры не отсоединяются.
- `patch_nodes.scaleFactor`: абсолютный нативный масштаб INSTANCE. Применяется `rescale(target/current)` до заданных width/height; отношение должно быть в пределах 0.01–100 для обратимого вызова API. Все шрифты потомков, включая скрытых, загружаются до первой записи. Для вложенного INSTANCE допустим только точный no-op. Масштабирование и патчи его предков/потомков требуют отдельных последовательных пакетов; при ошибке восстанавливаются исходный масштаб и размеры.
- `bind_variables`: необязательные парные UTF-16 `start/end`, поля `fontFamily` (STRING), `fontWeight` (FLOAT), `fontSize` (FLOAT), `lineHeight` (FLOAT), `fills` (COLOR с `paintIndex`). Диапазоны одного поля/краски не пересекаются. `fontWeight` в patch/textRuns по прежнему означает имя начертания — это отдельный старый интерфейс. Для числового веса загружаются точные доступные начертания вовлечённых семейств без собственной таблицы подстановки. Неверный ресурс, шрифт или диапазон блокирует пакет. Ошибка setter запускает откат значений и прежних aliases. Ответ содержит `actual` с прочитанными диапазонами.
- `set_reactions`: `resetScrollPosition` и `resetVideoPosition`. Для NAVIGATE отсутствие первого эквивалентно подтверждённому `true`, второго — `false`. `preserveScrollPosition` — обратное значение resetScrollPosition. Явное противоречие запрещено; неизвестные поля и изменения поведения не игнорируются. Клики в Present проверяются отдельно.

`inspect_selection(detail:"full")` возвращает `scaleFactor`, `booleanOperation`, `pointCount`, свойства списков и `textSegments` с красками и диапазонными `boundVariables`. `check-render-result` сравнивает новые свойства и GLASS без допуска, textRuns — по всем покрывающим сегментам. Неописанные свойства и визуальное сходство требуют отдельной проверки.

Блокировку старого Bridge можно снять только после свежего `get_status({fileKey})`: нужны `diagnostics.ready`, все три `diagnostics.current` и живой ответ Plugin API. `diagnostics.capabilityFileKey` равен назначению; `diagnostics.mcp.revision` совпадает с исходниками. `diagnostics.capabilities` перечисляет `text-lists-v1`, `glass-effects-v1`, `vector-properties-v1`, `text-range-variables-v1`, `navigate-scroll-default-v1`, `instance-scale-v1`. Без конкретного файла, живого ответа или при устаревшем runtime список пуст. Версия пакета сама по себе не подтверждает поддержку.

Локальный MCP-кандидат: `node ./src/server.mjs`, cwd корня плагина, существующий `FIGMA_LOCAL_STATE_DIR`. Завершите операции старого процесса, подключите новый и проверьте целевой fileKey. Персональная сборка — `npm run prepare:local`; перед обновлением рабочего каталога установки сохраните его копию. Проверки: `npm test`, `npm run schema:check`, `npm run verify`. Последняя проверяет новый MCP-каталог и не доказывает переключение уже открытого чата.

Внутри потомков INSTANCE свойства `isMask`, `maskType`, `x`, `y`, `rotation`, `layoutPositioning`, `constraints`, `minWidth`, `maxWidth`, `minHeight`, `maxHeight` также принимаются только как точный no-op. Проверка ancestors начинается с parent, поэтому размещение корневого INSTANCE остаётся допустимым. No-op сравнение не зависит от порядка ключей объекта, но не игнорирует поля и не использует числовой допуск. При записи и откате совпавшие свойства и размеры не назначаются повторно.

Для `fills`/`strokes` и gradient stops отсутствие `boundVariables` эквивалентно пустому `{}`: оба означают отсутствие aliases. Это предотвращает ненужный paint setter и пересчёт native boolean geometry. Непустые bindings, прочие поля и числа сравниваются строго; rollback не применяет неизменённые style ids повторно.

При `layout.direction:"none"` сохраняются неактивные `gap`, padding и alignment: их можно задавать без включения Auto Layout. `wrap`, `counterAxisSpacing`, `strokesIncludedInLayout`, `itemReverseZIndex` в этом режиме допускаются только при точном совпадении с native значением. Недопустимое изменение отклоняется до первой записи patch-пакета.

`set_node_variable_modes` задаёт явный режим коллекции на выбранных FRAME/INSTANCE без изменения библиотеки: обязательные `fileKey` и `bindings:[{nodeId,collectionKey,anchorVariableKey,modeName}]`, максимум 40. Capability `node-variable-modes-v1`; preflight проверяет цели, импорт, уникальное имя режима и шрифты потомков. Ответ содержит проверенные `variableModesVerification.checks`, при ошибке выполняется ограниченный откат собственных режимов.

`import_variables` импортирует ссылки на библиотечные переменные в файл назначения: обязательные `fileKey` и `variables:[{key,resolvedType,collectionKey?}]`, до 100 уникальных ключей. Ответ `complete:true` подтверждает весь набор и содержит проверенные ID назначения, типы и коллекции. При частичной ошибке подтверждённые записи остаются в `blockers[0].evidence.variables`; импорт не откатывается удалением ресурсов. После тайм-аута сначала проверьте `get_status` того же файла и завершение активной операции. Значения переменных и исходная библиотека не изменяются.

### Журнал типизированного вызова и неполное чтение

При `call-tool.mjs TOOL --args FILE --output DIR` клиент сохраняет `response.json` (полный MCP envelope), `result.json` (structuredContent либо единственный JSON text payload), PNG отдельно и `transport.json` (responseReceived, isError, exitCode, error, ограниченный stderr с маскированием credentials). Текст без JSON сохраняет прежний массив строк. Код выхода 1 может сопровождаться достоверным ответом `not_applied` или `rolled_back`: сначала прочитайте артефакты. Отсутствие ответа не доказывает отсутствие записи; клиент никогда не повторяет вызов автоматически. Полный envelope может содержать PNG/base64, поэтому не загружайте его целиком в контекст модели.

`inspect_selection` добавляет ordered `childIds` и `childCount` контейнерам, `parentId`/`childIndex` каждому узлу и `parentChildIds` корням запрошенных ветвей. Пропуски `maxNodes` содержат `nodeId`, `parentId`, `childIndex`. При дочитывании сверяйте родителя и порядок с исходным снимком; изменение дерева требует нового чтения. `render_screen` не объявляется идемпотентным: замена экрана меняет идентификаторы.

`resolve_variables` безопасно читает ранее подтверждённые ID библиотечных переменных, сверяет ключ, тип, коллекцию и режимы. После неизвестного результата `import_variables` сначала дождитесь готовности Bridge и проверьте результат этим read-only инструментом; повторный импорт без сверки запрещён. Отсутствие и ошибки чтения не считаются успешным восстановлением.

## Фоновая загрузка шрифтов

Целевой файл перед фоновой сборкой вынесите в отдельное открытое, несвёрнутое окно Figma Desktop, запустите Bridge и вернитесь к другому рабочему окну. Сначала выполните `render_screen` с `dryRun:true` и реальной спецификацией. Скрытая вкладка в одном окне может зависать на первой загрузке шрифта. [Общий порядок для CLI и MCP, проверенные условия и восстановление](skills/figma-local/references/background-fonts.md).
